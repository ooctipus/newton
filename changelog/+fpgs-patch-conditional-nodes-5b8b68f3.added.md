Add an experimental opt-in `FEATHER_PGS_PATCH_CONDITIONAL_NODES=1` that sorts the patch-friction contact pairs of `SolverFeatherPGS` under a conditional CUDA graph node on captured steps that do not keep their pairs through frame reuse (`FEATHER_PGS_PATCH_FRAME_REUSE`): the node skips the sort for empty contact frames and for the contact frame sorted last (the same `Contacts`, `contact_generation` and contact count), for example on the first step of a graph captured without a collision pass. It is opt-in because a graph that holds conditional nodes was measured slower to submit, which outweighed the skipped sorts on four of 21 Isaac Lab tasks (Kuka lift +3.8%, Kuka reorient +3.3%, an SO-101 keyboard task +1.2% and Ant +1.8%, measured with a node on every captured step). It is experimental because Nsight Systems node-level graph tracing fails with an illegal memory access on graphs that hold the node, which remains unexplained; the invalid reads that compute-sanitizer's memory checker reported in the pair sort inside the node come from its stream-ordered allocation tracking and disappear with `--track-stream-ordered-races no`. Set `FEATHER_PGS_PATCH_CONDITIONAL_NODES=1` before constructing the solver to enable it; unset, `0` or any other value keeps those sorts unconditional, and `get_path_selection()["routes"]["friction"]["conditional_nodes"]` records the choice and its reason. With the node, the capture pauses once per such step, so an event recorded before `step()` cannot be waited on after it; a step taken while a stream forked by the caller still holds unjoined work sorts unconditionally.
