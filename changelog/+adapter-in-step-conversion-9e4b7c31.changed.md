Convert Newton contacts inside the MuJoCo Warp step in `SolverMuJoCo` (through the `Callback.post_position` hook, when the installed MuJoCo Warp provides it): the conversion, the by-contact `dist` / `pos` refresh of substeps that keep the contact set, the collision wake and the dormant-contact injection now run after MuJoCo Warp's own wake pass and kinematics, from `xpos` / `xquat`, so the adapter's pre-step `sleep.wake` and `tree_awake` refresh launches and the separate refresh kernel disappear. Sleep and contact bookkeeping arrays are unchanged; MuJoCo Warp contact order and floating-point results differ only within solver round-off on the substep a tree is woken by a force while the contact set changes. The solver also sets `Option.fused_world_publish_derived` (MuJoCo Warp versions that have it) before every step: the fused per-world forward skips the derived data fields Newton never reads unless `body_qdd` / `body_parent_f` or sensors are requested, or the new `SolverMuJoCo.mjwarp_publish_derived` attribute is `True` (set it when reading `xmat`, `geom_xpos`, `site_xpos`, `cacc`, `cfrc_int`, ... from `mjw_data` directly). The new `SolverMuJoCo.publish_intermediate_joint_state` attribute (default `True`) lets substepping integrations skip the intermediate `joint_q` / `joint_qd` publish and run the `update_data_interval` re-sync on the first substep of a tick only. No migration needed.
