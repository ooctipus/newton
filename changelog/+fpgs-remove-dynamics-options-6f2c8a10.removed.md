Remove the `SolverFeatherPGS` options `parallel_tree`, `lazy_kinematics` and `grouped_dynamics`, and the no-op `publish_kinematics()` method. The solver chooses the grouped contact-response kernel from the scene data, where the in-kernel parallel tiers skip each world's rows; a scene that set `grouped_dynamics=True` without those tiers now runs the planned response kernel, which solves the same response summed in another order, so its results differ in the last bits. The other two options selected nothing.
